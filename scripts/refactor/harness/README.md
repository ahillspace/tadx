# Prepare the blocked 131-case G9 snapshot

This is the sole maintained preparer for the current 124 TADX action cases and seven selected Windows installer variants.
It replaces the former six-project preparation workflow.
The seven variants are selected exercises, not implicit passes or silent exclusions.
The two selected mutation cases are P-mutation-set and P-mutation-status; the mutation V examples are not in this source lock.

The preparer checks the 373-entry current-suite input lock before copying or transforming source.
The older six-project lock remains only as the provenance anchor for the exact extension.
An original file, exercise pair, patch anchor, or import closure that differs from the reviewed lock blocks preparation.
The current external suite must be supplied explicitly; the preparer never discovers older runs.

The single entry point requires an explicit current suite, a new ignored output directory, the accepted candidate identity and capability catalog, exact Windows and Linux native builds, the accepted CLI capture, private fixture authority, saved-consent evidence, and the exact accepted source archive.
Its options are --harness, --output, --candidate, --catalog, two --build values, --capture, --authority, --consent-evidence, and --source-archive.
The output is a blocked snapshot with 131 selected case IDs, source and binary hashes, patch records, and no live dispatch permission.
For the selected update case, the preparer validates the source archive against the accepted candidate and builds private Linux fixture binaries offline.
The source lock binds those assets to the accepted source, toolchain, tracked recipe, and Guidance hashes.
The preparer does not replace or rebuild either accepted candidate binary.

The fixed Windows worker and workflow use one reviewed gate and one host relay implementation.
The preparer copies the gate byte-for-byte and derives the relay's prepared import with one exact, recorded replacement.
The local host relay owns prewarmed job setup, same-job native result and cleanup proof, and lease-protected branch deletion.
The hosted worker receives only an exact one-file request child and a job-scoped GitHub read token.
No model, Tableau credential, real PAT, or arbitrary shell relay is sent to the hosted job.

The two selected mutation cases use a disposable network-none config at a canonical synthetic server and exact synthetic site.
Saved site consent and the legacy process/global values remain separate facts.
The private authority and consent evidence are hashed but not copied into the prepared source.
No real PAT may persist to the ordinary host config or credential store.
The user permits temporary test PAT storage only inside a disposable container.
Before launch, prove that the native store is container-scoped and destroyed after the task.

Ordinary CI runs the hermetic preparer, profile, worker, and broker tests on Linux and Windows.
The suite-dependent lock, mutation, and session tests require a separately supplied current-suite path and cannot silently skip in CI.
The final candidate still needs exact G0-G8 gates, source/build/Guidance provenance, fixture admission and native observers, effective Luna medium metadata, cleanup proof, and independent review.
There is no G9 pass until actual native task evidence establishes each selected outcome.
The grader must use transcript, native acknowledgement, and independently observed affected state, not final-answer formatting alone.
An intentional native refusal can satisfy a task; unavailable setup, provider, or cleanup evidence remains excluded or incomplete.
Missing timing, token, and turn values remain null.
