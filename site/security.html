Security & control

Powerful commands.Deliberate control.

Your agent can work with Tableau. You decide where it can make changes. Here is how TADX handles credentials, checks authority, and keeps those boundaries explicit.

The short version

New sites start with remote writes disabled. Credentials use your OS store. An optional managed policy adds administrator-controlled restrictions.

01 / Independent controls

Every write needs permission.

Enabling one control does not bypass the others. A request to publish a workbook is not permission for an agent to change your saved security settings.

1

Tableau permissions

The authenticated Tableau user must have the necessary rights on the actual target. TADX cannot grant itself access.

2

Saved site consent

Remote mutations must be enabled for the canonical server and exact Tableau site. New site settings default to disabled.

3

Managed policy

If configured, the machine-wide policy must allow the operation and remote mutations. Site consent cannot override it.

These are separate checks, not an execution sequence. Command validation, exact target resolution, and supported API requirements still apply.

What do preview and force mean?Inspect a change without treating the preview as permission.+

Supported commands expose --preview to inspect proposed changes without applying them. A preview may still need live reads and the capability IDs required to resolve its targets. Custom policy can deny those reads.

Neither --preview nor --force enables site consent or bypasses managed policy. A valid preview does not mean the later mutation is authorized.

tadx mutation status
tadx policy status
What if an agent keeps trying?CLI enforcement is different from guidance in a prompt.+

Agent Guidance tells agents to ask before changing saved site consent. Managed policy is an additional check enforced by TADX, not merely an instruction to the model. A blocked mutation does not become permitted because the agent retries or uses cached content.

An agent can request an administrator-authorized policy change. On an ordinary, unelevated Windows session, the policy installer requests elevation through Windows. Approving that request can change the policy. Keep agents unelevated and review approval prompts.

02 / Choose the mutation boundary

All templates allow reads.

Administrative reads, including users, groups, and permissions, are included. The built-in templates differ in the Tableau changes they allow, not the information they hide.

Observe & inspect

read-only

Read Tableau information and work with local artifacts. Do not change remote Tableau resources.

Tableau mutationsBlocked

Work with content

read-write-no-admin

Allow non-administrative changes. Block administrative mutations such as changing users, groups, or permissions.

Tableau mutationsNon-administrative only

Full supported access

superuser

Allow all currently supported operations, including administrative changes. Tableau permissions still apply.

Tableau mutationsAllowed by policy

All remote mutations still need saved site consent. Read-only is not a read-only disk: local operations such as refreshing caches and downloading artifacts remain available.

No template specified? The installer selects superuser. Choose --template read-only explicitly when you want to block Tableau mutations. Installing TADX itself does not install a managed policy.
Can I restrict individual reads or commands?Use a custom policy when the built-in choices are too broad.+

Yes. A managed policy contains an explicit allowlist of capability IDs and a separate remote-mutation setting. An administrator can remove read capabilities as well as write capabilities. Commands may also require permission for dependent operations.

Templates are snapshots of the current capability registry. Updating the CLI does not rewrite an installed policy; newly introduced IDs remain denied until an administrator updates the policy. Reinstalling a template replaces that snapshot and any custom edits at the selected destination.

The older admin template name is accepted as an alias for superuser. It is not a fourth access level.

03 / Authentication

A token, not your password.

TADX authenticates to Tableau using personal access tokens (PATs). Interactive login validates the PAT before saving it in the native OS credential store.

01 / STORENative OS credential store

The PAT name and secret are stored with a fingerprint of the Tableau target.

02 / REFERENCEOpaque configuration reference

Your configuration points to the saved record. It does not contain the PAT value.

03 / USECommand-local session

TADX retrieves the PAT when needed and uses the Tableau session token in memory for the command.

Where is a saved PAT stored?Windows Credential Manager, macOS Keychain, or Linux Secret Service.+
Windows
A generic credential in Windows Credential Manager.
macOS
A generic-password item in Keychain, accessed through the native security tool.
Linux
Secret Service over D-Bus. A reachable service and an accessible, unlockable collection are required.

The stored record is checked against the configured server and exact site before use. Native-store failures are reported; TADX does not fall back to saving the PAT as plaintext in its configuration.

When can an agent save or remove credentials?Persistent login needs your authorization; logout is not PAT revocation.+

An agent must have your explicit approval before persisting a PAT. tadx auth login is the persistence action: it prompts for the PAT, validates it, and saves it. It does not show a separate TADX confirmation dialog after validation.

tadx auth logout removes the local saved credential; it does not revoke the token in Tableau. Revoke a compromised or no-longer-needed PAT in Tableau itself.

What about automation, sessions, and logs?Environment variables are supported without putting secrets in command arguments.+

An environment profile can name environment variables for the PAT name and secret. A complete configured pair takes precedence over the stored credential. Protect the process environment and avoid placing secrets directly in shell commands or shared files.

Tableau session tokens are held in command-local memory. Persistent coordination state uses hashes and epochs, not raw PAT or session-token values. Job receipts may retain the opaque credential-derived coordination hash; it cannot authenticate to Tableau. TADX redacts credential-bearing output and diagnostics.

These controls do not protect against a compromised host, same-user malware, terminal recording, or another tool exposing a secret. See the full storage and session model.

04 / Administrator-controlled policy

Install once. Enforce locally.

Managed policy is optional and machine-wide. On Windows, TADX can create and protect the policy through a scoped administrator helper, without elevating the calling agent or terminal.

Version note: the Windows policy installer and revised template names describe the current development source. Older releases may differ. Check tadx policy install -h and the release notes for your installed version.
tadx policy install --template read-only
tadx policy status --full

Review the Windows approval prompt. Installation replaces the policy at the selected destination; it does not change saved Tableau site consent.

Where does it go? Can I choose another folder?Native Program Files by default, or a dedicated local directory.+

The default is the native Program Files directory followed by TADX\managed-policy.json. Use --output to choose the containing directory, not a JSON filename. The parent must exist and the directory must be dedicated to the policy.

tadx policy install --template read-only --output "C:\TADX-policy"

The protected, native 64-bit registry location HKLM\SOFTWARE\TADX\ManagedPolicy records the chosen directory. It stores neither the policy body nor credentials. User configuration cannot override this location.

What happens if I reinstall or switch folders?The selected file is replaced; old locations are left alone.+

Reinstalling writes a new policy from the selected template and replaces any existing managed-policy.json in that directory. Omitting --output always selects the default Program Files location, even after a custom installation. Include your custom folder again when you want to keep it active.

Switching directories updates the active location without deleting the old policy. Review the destination and template before approving elevation. Omitting --template selects superuser, not the previously installed template.

What does Windows protect?File, containing folder, and registry permissions do the enforcing.+

TADX requires protected ownership and permissions on the policy file, its immediate installation directory, and the registry locator. Path integrity, reparse-point, and file-link checks remain mandatory.

Permissions on folders above the policy, including the drive root, are also checked. Unsafe or unverifiable ancestor protection produces a warning, not a refusal to use the policy. TADX does not automatically change those permissions.

A protected file does not guarantee a protected path. Someone allowed to replace a folder above it could substitute another valid administrator-owned policy, including an older, more permissive one, between commands. Status distinguishes protected from path_protected; the loaded policy remains enforced when there is only an ancestor warning.

Use a fully protected path when you need protection against this substitution. An already elevated process can change protected policy, and Windows elevation settings determine whether approval or credentials are requested.

What if approval is cancelled or installation fails?A failed command does not always mean nothing changed.+

Cancelling elevation before the helper starts leaves the policy unchanged. After the helper starts, a failure can occur after the file was written or an existing active policy was replaced. TADX reports confirmed changes and the phase; it does not promise automatic rollback.

A present but invalid locator, or a missing policy at its selected location, blocks normal operations rather than silently falling back. Policy install, status, samples, validation, and help remain available for recovery.

Use the recovery and removal instructions ↗

How does this work on macOS and Linux?Manual administrator deployment today; not the Windows install flow.+

The policy location is /Library/Application Support/TADX/managed-policy.json on macOS and /etc/tadx/managed-policy.json on Linux. The current policy install command is Windows-only.

Unix deployment requires root ownership and protected write permissions on the policy and its ancestors, with platform-specific ACL and link checks. These checks intentionally differ from Windows. Follow the platform deployment instructions.

05 / Data on your machine

Local does not mean non-sensitive.

Workbooks, inventory, and recovery records can contain business information. Protect the machine, workspace locations, and backups even when remote writes are disabled.

What can TADX leave on disk?Configuration, content, caches, results, and recovery records.+
  • Configuration: server/site settings, saved mutation consent, workspace locations, and opaque credential references.
  • Workspaces: downloaded or authored Tableau artifacts and local metadata.
  • Inventory caches: SQLite records with names, IDs, relationships, and other cached metadata.
  • Results and recovery: the bounded last result, job receipts, and operation records that may include target paths and result payloads.

TADX does not provide a general encryption-at-rest or secure-deletion guarantee for these files. Operating-system access controls, disk protection, backup policy, and retention remain your responsibility. See exact locations and retention boundaries.

How are network connections protected?HTTPS for Tableau authentication and authorized requests.+

PAT sign-in requires HTTPS, as do requests carrying Tableau session authorization. The default CLI uses Go's standard certificate verification and environment proxy behavior. The shared transport rejects cross-origin redirects and HTTPS downgrades.

Enterprise proxies, the system's trusted certificate authorities, and the local environment remain part of the trust model. TADX does not make a compromised or incorrectly trusted host secure.

06 / Be clear about the limits

Controls, not a sandbox.

TADX checks its own operations. It cannot constrain every tool an agent can run, protect a compromised operating system, or remove privileges the agent already has.

Keep the agent unelevated.

Administrator or root authority can change protected policy and its permissions. An agent may request elevation; approving it authorizes the elevated operation. Review what is being requested instead of treating every approval prompt as routine.

What do installer checksums prove?Downloaded bytes match the release manifest, not an independent identity.+

The installers download release assets over HTTPS and verify SHA-256 against that release's checksums.txt. This checks consistency with the fetched manifest.

The assets and manifest share the release publishing trust chain. A matching checksum is not an independent publisher signature and does not protect against a compromised release account or build pipeline. You can inspect the installer scripts and release workflow in the repository before use.

Does Agent Guidance grant extra authority?Skills help an agent operate the CLI; they do not grant permissions.+

The installer and updater deploy TADX-owned Guidance for supported agent locations. That guidance does not configure Tableau authentication, enable mutation consent, or install a managed policy. It also does not prove that an agent host has loaded or followed the guidance.

Updates replace TADX-owned Guidance. Keep personal extensions separate. Tableau MCP is a separate connection and tool surface; a TADX policy does not govern MCP or direct Tableau API access through other tools.
